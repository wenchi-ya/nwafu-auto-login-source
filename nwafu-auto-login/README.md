# NWAFU Auto Login

适用于 Windows 的西北农林科技大学校园网自动认证工具。断网且识别到校园网络时，通过后台 Microsoft Edge 完成认证；正常联网时不打开浏览器。

使用一个 `setup.cmd` 完成安装和管理，同时支持**开机未登录、登录桌面后、锁屏时**的自动检查。另提供 `test.cmd` 进行手动可视测试。

这是非官方工具，目前针对以下 SRun 门户，不是通用校园网客户端：

<https://portal.nwafu.edu.cn/srun_portal_pc?ac_id=1&theme=pro>

## 功能

- 一次配置，注册同一个 Windows 计划任务：开机约 30 秒后、用户登录时、每分钟检查。
- 在当前 Windows 账户下以普通权限运行，支持用户尚未登录的情况。
- 正常联网时跳过；断网时根据校园认证跳转/页面提示或指定的 Windows 网络名称判断是否尝试认证。
- 校园网凭据通过 Windows DPAPI 加密保存到本机用户目录。
- 认证失败后逐步延长重试间隔，连续失败 5 次暂停，避免频繁提交。
- 后台运行不弹出浏览器和错误窗口；手动测试可以显示浏览器。
- 并发锁防止定时任务和手动操作同时认证，日志自动轮转。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 11；代码使用 Windows 专有 API |
| Python | 3.10 或以上，推荐 3.12，安装时包含 Python Launcher |
| 浏览器 | 已安装 Microsoft Edge，无需下载 Playwright 浏览器 |
| 权限 | 安装任务时需管理员授权，必须是保存校园网凭据的同一账户 |
| Windows 账户 | 有非空账户密码，允许创建密码式计划任务；Windows Hello PIN 不能替代密码 |
| 网络 | 首次安装依赖时需要能访问 Python 包源；自动认证时能访问校园门户 |

Python 下载：<https://www.python.org/downloads/windows/>

## 快速开始

1. 下载或克隆本项目，放到长期保留的本地目录，例如 `E:\campus-auto-login`。不要在 ZIP 内运行。
2. 首次安装前手动完成校园网认证，或临时连接热点，确保可以下载依赖。
3. 双击 **`setup.cmd`**，选择 **1：安装/更新**，接受管理员权限提示。
4. 首次使用时，在本机输入校园网账号和密码。密码输入不显示。
5. 根据提示配置校园网络名称。只有确认是校园网络时才填写当前显示的名称；不确定可以留空，留空时仅依赖认证跳转/页面提示识别。不要填写热点或家庭 Wi-Fi 的名称。
6. 在凭据窗口输入 **Windows 账户密码**，不是校园网密码，也不是 PIN。
7. 出现绿色 **`SUCCESS`**，表示任务已注册并验证三个触发条件。安装器还会请求一次后台检查。
8. 在校园网需要认证时运行 **`test.cmd`**，确认页面可以自动登录。

校园网密码用于认证，Windows 密码用于让计划任务在未登录时运行，两者用途不同。Windows 密码交由任务计划程序管理，不写入项目文件、日志或命令行。

`SUCCESS` 表示任务配置成功，不代表校园网已经认证成功。网络结果请查看测试输出或运行日志。

## 日常管理

双击 `setup.cmd`：

| 选项 | 操作 |
| --- | --- |
| 1 | 安装/更新依赖和统一自动任务；已保存的校园网配置可保留 |
| 2 | 修改校园网账号、密码、网络名称，同时解除连续失败暂停 |
| 3 | 查看任务状态、最近退出结果和认证暂停状态 |
| 4 | 停止并删除当前账户的自动任务，保留本机凭据和日志 |
| 5 | 手动可视测试，与 `test.cmd` 相同 |
| 0 | 退出 |

修改校园网密码使用选项 2，不需要重新输入 Windows 密码。修改 Windows 账户密码使用选项 1。

## 运行行为

### 开机、锁屏和睡眠

| 电脑状态 | 行为 |
| --- | --- |
| 开机，尚未登录 Windows | 启动约 30 秒后检查；网络未就绪时后续每分钟检查 |
| 登录桌面 | 触发一次检查，之后继续每分钟检查 |
| 锁屏但电脑仍在运行 | 继续后台检查 |
| 真正睡眠、休眠或关机 | 不运行，不会为了检查而定时唤醒电脑 |
| 从睡眠恢复 | 后续计划任务继续检查，可能需要等待约一分钟及网络恢复 |

登录前认证的前提是网络已经自动连接，项目目录和 Python 在登录前就可以访问。登录后才解锁的磁盘、用户手动建立的 VPN、登录后才连接的无线网络不满足此前提。工具不会绕过 Windows 登录验证，也不会自动登录 Windows。

### 设备数量超限和失败重试

每分钟执行的是**检查**，不是每分钟提交密码。认证失败后通常依次等待 5、10、20、40 分钟才进行下一次尝试；连续失败 5 次后暂停。检测到部分常见密码错误文案时会提前暂停。

账号登录设备数量已满时，门户可能拒绝新设备，脚本会按普通失败处理。目前没有专门识别设备超限，也不会主动踢掉其他设备。认证系统是否让新设备替换旧设备，由学校规则决定。

释放其他设备名额后，如果脚本已暂停，通过菜单 2 重新配置以恢复自动尝试；也可用 `test.cmd` 主动测试，认证成功后会清除暂停状态。密码错误判定依赖页面文案，无法覆盖所有错误提示。

### 其他 Wi-Fi 和手动测试

正常联网时跳过认证。在非校园网络断网时，如未发现校园门户提示且网络名称不匹配，也会跳过。自动识别是启发式判断，网络名称重复或特殊跳转可能导致误判。

**`test.cmd` 是主动操作**：无法联网时直接尝试固定校园门户，忽略自动识别、暂停和重试间隔；不会向其他 Wi-Fi 的登录页面填写密码。已经联网时仍然直接跳过。后台忙碌时手动操作最多等待 30 秒，超时会明确提示本次未执行。

日常检查只运行短暂的 Python/网络请求；真正认证时启动后台 Edge，会有一定 CPU 和内存占用。

## 凭据与日志

本机数据目录：

```text
%LOCALAPPDATA%\NWAFUAutoLogin\
├── credentials.bin   # 当前用户 DPAPI 加密的校园网账号密码
├── config.json       # 指定的校园网络名称
├── state.json        # 重试次数、等待时间和暂停状态
├── run.lock          # 并发锁
└── activity.log      # 轮转日志，另保留最多两份历史日志
```

按 Win+R，粘贴 `%LOCALAPPDATA%\NWAFUAutoLogin` 即可打开。不要提交这些文件到公开仓库。DPAPI 保护不等于防御同一用户下的恶意程序：相同用户权限的程序可能解密这些凭据。

浏览器认证仅允许访问 `https://portal.nwafu.edu.cn` 的标准 HTTPS 端口，保留证书校验，使用临时浏览器环境。脚本不记录账号密码、页面原文或认证请求参数。联网检测请求微软和 Mozilla 的 HTTP 检测地址，不携带校园凭据；任一预期响应成功视为联网，并不保证所有网站都可访问。

## 常见问题

**任务安装失败 / 密码不接受**

确认输入的是 Windows 账户密码而非 PIN，并使用保存校园凭据的同一账户授权。空密码、无密码账户或组织策略可能禁止这种任务。错误发生时会显示“未完成”，不要视为安装成功。

**任务显示运行过，但没有认证**

通过菜单 3 检查任务和暂停状态，并查看日志。任务结果为 `0` 也可能表示网络正常、未识别校园网络、等待重试或已有其他实例，不等同于认证成功。`1` 通常表示失败或暂停，`2` 表示手动操作等待锁超时。

**未识别校园网络**

连接校园网后，通过菜单 2 填入显示的 Windows 网络名称。网络名称不一定等于 Wi-Fi SSID，使用脚本显示的名称。

**网页打不开、证书错误或按钮找不到**

先在 Edge 手动打开门户，检查校园连接和系统时间。不要忽略证书错误。若学校改版，需要调整 `campus_login.py` 中 `login()` 的选择器；如果学校新增资源域名，需要审查后调整允许访问的地址。

**更换 Python 或移动目录后不能运行**

保留新目录并重新执行菜单 1，重建/修复虚拟环境并更新任务路径。若当前 Python 已卸载，先安装满足要求的 Python。

**如何卸载**

先通过菜单 4 停用任务，再删除项目目录。如果还要清除保存的账号密码和日志，手动删除 `%LOCALAPPDATA%\NWAFUAutoLogin`。

## 开发与验证

在 Windows、Python 3.10+ 下，从项目根目录执行：

```powershell
python -m unittest discover -s tests -v
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test_manage.ps1
```

测试使用临时目录、测试凭据和模拟任务注册，不修改真实账号配置、不提交真实校园网认证、不创建真实计划任务。覆盖凭据加解密、跨进程并发锁、网络识别、暂停/恢复，以及统一任务的触发器、运行权限和注册校验。

现有认证逻辑曾由使用者在校园网环境验证成功；统一安装流程经过本地回归检查。不同电脑上的密码式任务注册、开机未登录状态和校园门户行为，仍需本机安装及重启实测。
