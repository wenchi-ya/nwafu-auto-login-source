# NWAFU Auto Login

[更新记录](CHANGELOG.md) · [参与开发](CONTRIBUTING.md) · [问题反馈](https://github.com/wenchi-ya/nwafu-auto-login-source/issues)

适用于 Windows 的西北农林科技大学校园网自动认证工具。校园门户确认当前设备未认证时，通过后台 Microsoft Edge 直连完成认证；已认证时不打开浏览器。

使用一个 `setup.cmd` 完成安装和管理，同时支持**开机未登录、登录桌面后、锁屏时**的自动检查。另提供 `test.cmd` 进行手动可视测试。

这是非官方工具，目前针对以下 SRun 门户，不是通用校园网客户端：

<https://portal.nwafu.edu.cn/srun_portal_pc?ac_id=1&theme=pro>

## 功能

- 一次配置，注册同一个 Windows 计划任务：开机约 30 秒后、用户登录时、每两分钟检查。
- 在当前 Windows 账户下以普通权限运行，支持用户尚未登录的情况。
- 优先直连查询校园门户的认证状态，避免 VPN 或检测地址白名单导致“能访问外网就跳过”的误判；状态不可确认时回退到联网检测和校园网络识别。
- 校园网凭据通过 Windows DPAPI 加密保存到本机用户目录。
- 固定每两分钟检查；认证失败后下次检查继续尝试，不累计失败次数、不延长间隔、不自动暂停。
- 后台运行不弹出浏览器和错误窗口；手动测试可以显示浏览器。
- 并发锁防止定时任务和手动操作同时认证，日志自动轮转。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 11；代码使用 Windows 专有 API |
| Python | 3.10 或以上，推荐 3.12，安装时包含 Python Launcher |
| 浏览器 | 已安装 Microsoft Edge，无需下载 Playwright 浏览器 |
| 权限 | 安装任务时需管理员授权，必须是保存校园网凭据的同一账户 |
| Windows 账户 | 有非空账户密码，允许创建密码式计划任务；Windows Hello PIN 不能替代密码 |
| 网络 | 首次安装依赖时需要能访问 Python 包源；自动认证时能访问校园门户 |

Python 下载：<https://www.python.org/downloads/windows/>

## 快速开始

1. 下载或克隆本项目，放到长期保留的本地目录，例如 `E:\campus-auto-login`。不要在 ZIP 内运行。
2. 首次安装前手动完成校园网认证，或临时连接热点，确保可以下载依赖。
3. 双击 **`setup.cmd`**，选择 **1：安装/更新**，接受管理员权限提示。
4. 首次使用时，在本机输入校园网账号和密码。密码输入不显示。
5. 根据提示配置校园网络名称。只有确认是校园网络时才填写当前显示的名称；不确定可以留空，留空时依赖门户状态或认证跳转/页面提示识别。不要填写热点或家庭 Wi-Fi 的名称。
6. 在凭据窗口输入 **Windows 账户密码**，不是校园网密码，也不是 PIN。
7. 出现绿色 **`SUCCESS`**，表示任务已注册并验证三个触发条件。安装器还会请求一次后台检查。
8. 在校园网需要认证时运行 **`test.cmd`**，确认页面可以自动登录。

校园网密码用于认证，Windows 密码用于让计划任务在未登录时运行，两者用途不同。Windows 密码交由任务计划程序管理，不写入项目文件、日志或命令行。

`SUCCESS` 表示任务配置成功，不代表校园网已经认证成功。网络结果请查看测试输出或运行日志。

## 日常管理

双击 `setup.cmd`：

| 选项 | 操作 |
| --- | --- |
| 1 | 安装/更新依赖和统一自动任务；已保存的校园网配置可保留 |
| 2 | 修改校园网账号、密码、网络名称 |
| 3 | 查看任务状态、最近退出结果和认证策略 |
| 4 | 停止并删除当前账户的自动任务，保留本机凭据和日志 |
| 5 | 手动可视测试，与 `test.cmd` 相同 |
| 0 | 退出 |

修改校园网密码使用选项 2，不需要重新输入 Windows 密码。修改 Windows 账户密码使用选项 1。

从旧版升级后，请执行一次选项 1，将已安装计划任务更新为每两分钟检查；可保留原校园网配置。旧版 `state.json` 不再读取或写入，其中的失败次数、等待时间和暂停状态不再生效，无需手动删除。

## 运行行为

### 开机、锁屏和睡眠

| 电脑状态 | 行为 |
| --- | --- |
| 开机，尚未登录 Windows | 启动约 30 秒后检查；网络未就绪时后续每两分钟检查 |
| 登录桌面 | 触发一次检查，之后继续每两分钟检查 |
| 锁屏但电脑仍在运行 | 继续后台检查 |
| 真正睡眠、休眠或关机 | 不运行，不会为了检查而定时唤醒电脑 |
| 从睡眠恢复 | 后续计划任务继续检查，可能需要等待约两分钟及网络恢复 |

登录前认证的前提是网络已经自动连接，项目目录和 Python 在登录前就可以访问。登录后才解锁的磁盘、用户手动建立的 VPN、登录后才连接的无线网络不满足此前提。工具不会绕过 Windows 登录验证，也不会自动登录 Windows。

### 设备数量超限和失败重试

每两分钟执行一次**检查**。优先向固定 HTTPS 门户的 `/cgi-bin/rad_user_info` 接口查询当前设备状态：明确已认证时跳过，明确未认证时尝试直连认证，即使 VPN 使外网检测地址可访问也不会跳过。状态查询失败或返回无法识别的内容时，回退到原有联网检测和校园网络识别，不将接口异常当作未认证。

认证失败、浏览器异常或出现密码错误提示后，下次检查仍会继续尝试，不累计失败次数，不延长检查间隔，也不自动暂停。已有实例仍在运行时跳过本次检查，避免并发认证。唤醒后网络名称查询超时会记录警告，不再显示误导性的“请先首次配置”。

账号登录设备数量已满时，门户可能拒绝新设备，脚本会按普通失败处理。目前没有专门识别设备超限，也不会主动踢掉其他设备。认证系统是否让新设备替换旧设备，由学校规则决定。

释放其他设备名额后，等待下一次检查即可；也可用 `test.cmd` 主动测试。密码错误判定依赖页面文案，仅用于日志提示；修改校园网密码后请通过菜单 2 更新配置。

### 其他 Wi-Fi 和手动测试

在其他网络上，校园门户通常不可达；此时正常联网就跳过，断网且没有校园门户提示、网络名称也不匹配时同样跳过。如果固定 HTTPS 门户确实可达并明确返回未认证，则会对该门户尝试认证。回退的网络名称和跳转识别属于启发式判断，可能误判。

**`test.cmd` 是主动操作**：优先检查门户状态，未认证时直连认证；状态不可确认且无法联网时，忽略校园网络自动识别并尝试固定校园门户。已认证，或状态不可确认但外网检测正常时跳过。不会向其他 Wi-Fi 的登录页面填写密码。后台忙碌时手动操作最多等待 30 秒，超时会明确提示本次未执行。

日常检查只运行短暂的 Python/网络请求；真正认证时启动后台 Edge，会有一定 CPU 和内存占用。

## 凭据与日志

本机数据目录：

```text
%LOCALAPPDATA%\NWAFUAutoLogin\
├── credentials.bin   # 当前用户 DPAPI 加密的校园网账号密码
├── config.json       # 指定的校园网络名称
├── run.lock          # 并发锁
└── activity.log      # 轮转日志，另保留最多两份历史日志
```

按 Win+R，粘贴 `%LOCALAPPDATA%\NWAFUAutoLogin` 即可打开。不要提交这些文件到公开仓库。DPAPI 保护不等于防御同一用户下的恶意程序：相同用户权限的程序可能解密这些凭据。

浏览器认证仅允许访问 `https://portal.nwafu.edu.cn` 的标准 HTTPS 端口，保留证书校验，使用临时浏览器环境并禁用 Service Worker。脚本不记录账号密码、页面原文、状态接口的用户资料或认证请求参数。日志记录检查开始、状态判断、登录框就绪及提交阶段。登录成功以校园门户确认已认证为准。

门户状态查询使用直连 HTTPS，不跟随跳转、不携带保存的凭据。作为回退的联网检测请求微软和 Mozilla 的 HTTP 检测地址；任一预期响应成功视为联网，并不保证所有网站都可访问，也不能单独证明校园网已认证。

认证专用 Edge 默认使用 `--no-proxy-server` 直连，绕过系统代理和 PAC 自动代理；后台认证和手动可视测试均生效，不修改 Windows、代理客户端或日常浏览器的代理设置。该参数的行为见 [Chromium 官方说明](https://new.chromium.org/developers/design-documents/network-settings/)。

此设置不能绕过 TUN／虚拟网卡、系统路由或 DNS 接管。若代理客户端开启后仍无法认证，可先断开代理再测试，判断是否存在这类影响。需要在校园网未认证的情况下保持代理连接，运行 `test.cmd` 验证实际效果。只更新认证代码无需重新注册计划任务，下一次运行即生效。

## 常见问题

**任务安装失败 / 密码不接受**

确认输入的是 Windows 账户密码而非 PIN，并使用保存校园凭据的同一账户授权。空密码、无密码账户或组织策略可能禁止这种任务。错误发生时会显示“未完成”，不要视为安装成功。

**任务显示运行过，但没有认证**

通过菜单 3 检查任务状态，并查看日志。任务结果为 `0` 也可能表示网络正常、未识别校园网络或已有其他实例，不等同于认证成功。`1` 通常表示失败，`2` 表示手动操作等待锁超时。

**未识别校园网络**

连接校园网后，通过菜单 2 填入显示的 Windows 网络名称。网络名称不一定等于 Wi-Fi SSID，使用脚本显示的名称。

**网页打不开、证书错误或按钮找不到**

先在 Edge 手动打开门户，检查校园连接和系统时间。不要忽略证书错误。若学校改版，需要调整 `campus_login.py` 中 `login()` 的选择器；如果学校新增资源域名，需要审查后调整允许访问的地址。

**更换 Python 或移动目录后不能运行**

保留新目录并重新执行菜单 1，重建/修复虚拟环境并更新任务路径。若当前 Python 已卸载，先安装满足要求的 Python。

不要将 `.venv` 从其他电脑或其他 Python 版本直接复制过来。若出现 `No module named 'greenlet._greenlet'`，可在项目目录打开 PowerShell，重新安装与当前 Python 匹配的依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install --force-reinstall -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -c "from playwright.sync_api import sync_playwright"
```

这些命令需要能访问 Python 包源。若虚拟环境内的 Python 本身无法启动，请先将旧 `.venv` 改名备份，再运行菜单 1 创建新的本机环境；校园网凭据保存在用户数据目录中。

**如何卸载**

先通过菜单 4 停用任务，再删除项目目录。如果还要清除保存的账号密码和日志，手动删除 `%LOCALAPPDATA%\NWAFUAutoLogin`。

## 开发与验证

在 Windows、Python 3.10+ 下，从项目根目录执行：

```powershell
python -m unittest discover -s tests -v
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\test_manage.ps1
```

测试使用临时目录、测试凭据和模拟任务注册，不修改真实账号配置、不提交真实校园网认证、不创建真实计划任务。覆盖凭据加解密、跨进程并发锁、网络识别、失败后持续重试、忽略旧版暂停状态，以及统一任务的两分钟触发间隔、运行权限和注册校验。

现有认证逻辑曾由使用者在校园网环境验证成功；统一安装流程经过本地回归检查。不同电脑上的密码式任务注册、开机未登录状态和校园门户行为，仍需本机安装及重启实测。

GitHub Actions 在 Windows 上运行 Python 3.10、3.12、3.13 的依赖导入及离线回归测试，不会访问校园门户、提交真实账号或注册计划任务。代理直连与校园门户访问的本地验证范围见 [更新记录](CHANGELOG.md)。

欢迎提交问题和修复。报告问题时提供 Windows/Python/Edge 版本、操作步骤及脱敏的错误信息，不要附账号密码、凭据文件或完整认证请求。
